# 执行纪律

## 授权

不自行提交、不改预先暂存、不自动恢复旧包、不覆盖已有证据。每次构建、签名、安装或设备操作按当前任务授权执行，历史文档中的同意不延伸到新任务。

服务、守护进程、容器、隧道、后台压力及自动唤醒/解锁默认不执行。不要为验证擅自改息屏、系统策略、设备类型、权限或 Profile。构建和主机检查不是手机功能证明。

## 敏感材料

不读取或打印 Profile、签名配置/env、证书、密钥、密码及私密签名日志。签名仅将已批准的 Profile 路径交给既有外部签名脚本，不另造签名流程。`sign-private.txt` 不属于可读证据。

## 数据与证据

保留 `native/{home,usr,tmp}`、用户文件、历史、字体及背景；不卸载清数据。新复验使用新目录，保留失败输入、原始日志和中间结果。不得伪造输出、改目标字节来制造通过，或将权限拒绝解释成未证实的系统原因。

每次报告分清：源码检查、编译成功、HAP 内容、安装回执、真实功能及屏幕交互。`recorded`、启动成功或版本输出都不能替代功能断言。已知限制应写“未验证”，不扩大为绝对不可能。

运行实现的约束分别属于 [进程生命周期](process-lifecycle.md)、[ELF 兼容层](elf-runtime.md) 与 [软件交付](distribution.md)，不在此重复维护。
